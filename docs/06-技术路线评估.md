# 技术路线评估（2026-11-07）

> 背景：项目变复杂，需要在四条路线中做选择。
> 本文基于**实测证据**，不是推测。每条结论都标注了证据来源。

---

## 一、当前路线（方案 0：PC 端 ADB 采集）—— 已跑通

### 已验证事实
| 项 | 证据 |
|---|---|
| 导航路径可自动化 | 用户指认 + `xqd.py` 实测跑通 |
| 课名可一次性取全 | WebView 一次 dump 含整营课名（`docs/01` 第四节） |
| fileId 可绑定 | 清单 mtime 差分，0.7 秒/节 |
| 下载链路完整 | DRM 走明文孪生，ffprobe 校验一致 |
| 已有 UI 工具 | `ui.html` + `xqd_server.py` 可用 |

### 弱点
1. **依赖模拟器常驻**：MuMu 必须开着，PC 不能休眠。
2. **UI 自动化脆弱**：App 改版 / WebView 滚动行为变化就要重调。
3. **每个营要逐节播放绑定**：70 节约 1 分钟，可接受但不快。
4. **签名会过期**：`t` 偏移服务器时钟 ~4.8 小时，需重新绑定。

## 二、三条未试方案的实测评估

### 方案 1：做成安卓端下载工具（APK）

**本质**：把 `xqd.py` 的 ADB 逻辑改成 App 内部逻辑，仍走 UI 自动化。

| 维度 | 评估 |
|---|---|
| 可行性 | ✅ 高。root 可用（实测 `adbd is already running as root`），能读 App 私有目录 |
| 工作量 | 中等。需处理 `uiautomator` 替代（用 AccessibilityService 或直接读 View 树） |
| 优点 | 不依赖 PC、不依赖模拟器；可后台跑；不占 PC 资源 |
| 缺点 | **仍要靠 UI 自动化**，继承了方案 0 的全部脆弱性；且**分发/安装麻烦**（模拟器上装 APK 比跑脚本麻烦） |
| 关键判断 | **不解决根本问题**。只是把同样的脆弱逻辑换个壳 |

**结论**：❌ 不推荐。它把"PC 脚本"翻译成"Android App"，工作量增加但可靠性没提升。

---

### 方案 2：做成 App 内插件（Xposed / LSPosed 模块）

**本质**：注入 App 进程，直接调用它的内部方法。

| 维度 | 评估 |
|---|---|
| 可行性 | ✅ 高。root 已有，`base.apk` 已提取在 `cache-analysis/` |
| 优点 | **最干净**。能直接拿到 App 的登录态、签名逻辑、课程数据；UI 就挂在原生课程列表里，天然满足"每节课旁加下载按钮"的诉求 |
| 缺点 | 需要 Xposed/LSPosed 环境；App 升级后 hook 点可能失效；写 hook 调试成本高 |
| 关键判断 | ✅ **技术上最优**。但对"教学场景临时导出"这个目标来说，**投入产出比失衡** |

**结论**：⚠️ 技术上最优，但**对本目标过重**。除非打算长期维护。

---

### 方案 3：直接走服务器 API（登录 → 拿课程列表/下载链接）

**本质**：不走 UI，直接调业务 API。

#### 🔑 本轮实测的重大突破

之前 `q_api.py` 里那 10 个 API 路径**全是猜的**（全 404）。本轮从 WebView 的 JS bundle（`webcache/` 483 个文件 + HTTP 缓存 1705 个文件）中**提取到了 305 个真实 `/gate/` 端点**，并**还原了完整鉴权链路**。

**已确认的事实**：

| 项 | 内容 | 证据 |
|---|---|---|
| API 网关路径 | `https://m.qianliao.net/financial/api/gate/<端点>` | 实测 403 + 业务 JSON |
| 前端页面 host | `m.qianliao.net` / `m1.xqdaolove.com` | WebView 缓存里的页面 URL |
| 端点调用方式 | **POST** + JSON body | JS 源码：`{url:"/gate/course/playListOfCourse", body:{campId}}` |
| 关键端点 | `/gate/course/myCourseListV2`（我的课程列表）<br>`/gate/course/playListOfCourse`（营内课程列表）<br>`/gate/course/getCoursePlayUrl`（拿播放链接）<br>`/gate/course/getSimpleCampDetail`（营详情） | JS bundle 提取 |
| 已知 campId | `5721891467` / `3485705003` / `1491668059` | WebView 缓存 URL |
| 鉴权形态 | 微信 OAuth。403 响应直接给出授权 URL：<br>`appid=wx41c22231d32cea4c`、`scope=snsapi_userinfo`、<br>`redirect_uri=https://m.qianliao.net/financial/api/gate/course/myCourseListV2` | 实测 403 响应体 |
| 已有凭据 | `rsessionId` / `userId` / `cUserId` / `uid` / `caller=app_edu` / `HMACCOUNT`（**值不落仓库**，见 `xqd_creds.py`） | root 读 Cookie 库（**明文存储**） |
| 已知课程/主题 ID | `topicId=34161831601` / `34161610606` / `periodId=115108835380` | WebView 缓存 URL |

**尚未解决的一环**：
- `rsessionId` cookie 单独用会被判"无权限访问"（code 110）。
- 需要**微信 OAuth 的 code** 或**App 原生层的 token**（App 是原生+WebView 混合，`updateAppLoginToken` 说明有独立登录态）。
- 推测路径：让 App 完成一次微信授权 → 从 App 侧拿到 token → 或直接用 WebView 已授权的会话。

#### 难度判断

| 环节 | 难度 | 说明 |
|---|---|---|
| 拿到登录态 | ⭐⭐⭐ | 核心难点。App 已登录，token 就在设备上（root 可读），但要找到它并搞清怎么用 |
| 调通课程列表 | ⭐ | 端点/参数都已明确，通了鉴权就是一行 JSON |
| 拿下载链接 | ⭐⭐ | `/gate/course/getCoursePlayUrl` 参数已知；但 VOD 签名 `sign`/`t` 仍需 server 签发 |

**结论**：✅ **最推荐**。这是唯一能真正**去掉 UI 自动化依赖**的路线，而且**最难的部分（端点发现 + 鉴权链路还原）本轮已经完成了 80%**。

## 四、建议

### 分阶段推进，不要二选一

**第 0 阶段（现在）**：继续用方案 0 把课导完。
> 工具已可用，剩「其余营 sweep + 全量下载」。这是**交付用户当下需求**的最短路径。

**第 1 阶段（并行投入）**：攻方案 3 的登录态。
> 目标只有一个：**让 `/financial/api/gate/course/playListOfCourse` 返回 JSON**。
> 一旦通了，整个工具架构可以重写为纯 API + Web UI，
> 彻底摆脱模拟器依赖，也顺带解决"课程列表要滚动采集"的麻烦。

**第 2 阶段（按需）**：若第 1 阶段卡住，再考虑方案 2（插件）作为备选。
> 方案 1 明确不推荐 —— 它只换壳不换病。

### 为什么推荐方案 3 而不是方案 2

- 方案 3 的**难点已经解掉大半**（端点、参数、鉴权形态、真实 campId/topicId 都有了）。
- 方案 3 完成后**不再依赖 App**，App 升级也不影响。
- 方案 2 虽然优雅，但要维护 hook，App 一升级就可能失效；对"临时导出到教学大屏"这个场景，
  **不值得投入**。

### 关键风险提示

- **方案 3 成功后，DRM 怎么处理需要重新验证**。
  现在的 DRM 绕过依赖"同目录明文孪生 + 时长校验"。
  走 API 拿到的是 `getCoursePlayUrl` 返回的 URL，可能直接是 DRM 清单。
  → **孪生机制应该仍然可用**（它基于 CDN 目录结构，与 API 无关），但要重新验证。
- **版权提醒**：导出的是用户**已付费订阅**的课程，用于自己课堂播放。
  长期/大范围使用建议向官方（班主任 / service@qlchat.com）申请课堂离线授权。

## 五、下一步的具体待验证项（方案 3）

按优先级：

1. **在 App 的 WebView 里打开 API URL**，看能否直接返回 JSON
   （WebView 已带微信 OAuth 会话，理论上可行）。
   → 这是最快的一锤定音。
2. 从 App 的 `shared_prefs` / DB 里找**原生登录 token**（不是 cookie 的 `rsessionId`）。
   已知：`com.qlchat.xingqudao_preferences.xml`、`qlChatCourses.db`、`ua.db`、`dim.db` 等。
3. 若 1、2 都失败：走**微信 OAuth 完整流程**（模拟器上 App 已登录微信，
   可自动完成授权拿 code），用 code 换 token。

验证成功标志：
```json
{"state":{"code":0,...},"data":{"courses":[...]}}
```
