## 二、技术栈与版本口径

| 项 | 值 |
|---|---|
| 目标框架 | .NET 8（`net8.0`），GUI 固定 `win-x64` 自包含单文件 |
| 界面框架 | Avalonia **11.3.23**（Avalonia / Desktop / Fluent / Inter，Debug 额外加 Diagnostics） |

版本号需要同步的位置（改版本时逐处核对）：

| 位置 | 用途 |
|---|---|
| `Xqd.Avalonia.csproj` → `<PkgVersion>` | **唯一来源**：程序集名 `xqd-downloader-v1.7.1`、文件版本 |
| `Xqd.Core/States.cs` → `States.AppVersion` | 界面底栏与「关于」显示 |
| `xqd-avalonia/build.cmd` → `VER=1.7.1` | 本地构建默认版本（可命令行覆盖） |
| `xqd/__init__.py`、`pyproject.toml` | Python 核心库版本（仅提示用） |
| `release.yml` | 发布时按 **tag** 传 `-p:PkgVersion=`，并与 csproj 比对、警告不一致 |

## 三、运行环境与依赖

| 项 | 说明 |
|---|---|
| 操作系统 | Windows 10 / 11 x64（MuMu 授权只在 Windows 上有意义，故不跨平台） |
| .NET 运行时 | **不需要**（运行时打进 exe）；本机构建需 .NET 8 SDK |
| ffmpeg / ffprobe | **必需**（分片转封装、成品时长校验）。查找顺序：`~/.xqd_tool/ffmpeg/bin` → `tools.json` 点选 → `XQD_FFMPEG_DIR` → PATH；缺失可一键装 |
| MuMu 模拟器 | **可选**，仅「重新授权」时需要；日常启动用本机缓存授权。定位走七级探测（见 docs/10 第八节） |
| adb | 仅 `--mode adb` 的旧数据源需要；API 模式不启 adb、不依赖设备 |
| 网络 | 业务网关与 CDN 请求**必须禁用系统代理**（否则被代理吞成 HTML） |
| 业务域名 | 原生 `app.qianliao.net`；Web 侧 `m.qianliao.net` / `m1.xqdaolove.com` / `m1.xqdaolove.cn` |

环境变量（手工指定时优先于自动探测）：

```
XQD_FFMPEG_DIR      ffmpeg/ffprobe 所在目录
XQD_MUMU_MANAGER    MuMuManager.exe 全路径
XQD_MUMU_HOME       MuMu 安装根目录
XQD_ADB             adb.exe 全路径
XQD_ADB_DEVICE      固定设备地址（如 127.0.0.1:16384）
XQD_COOKIE / QLD_COOKIE   直接给 cookie，跳过模拟器授权
XQD_TEST_HOME       回归/自测：把配置、历史、分片缓存隔离到临时目录
```

## 四、目录与配置

| 路径 | 内容 |
|---|---|
| `%USERPROFILE%\.xqd_tool\config.json` | 下载目录、画质、`mode`、`auto_launch`、`auto_close`、分片并发 |
| `%USERPROFILE%\.xqd_tool\history.json` | 下载历史（`{"version":1,"items":[…]}`，上限 500 条） |
| `%USERPROFILE%\.xqd_tool\parts\<md5(路径)[:16]>\` | 分片缓存（续传本钱） |
| `%USERPROFILE%\.xqd_tool\cookie.txt` | 本机授权（仓库之外，绝不入库） |
| `%USERPROFILE%\.xqd_tool\tools.json` | 用户点选过的 ffmpeg / MuMuManager 路径 |
| `%USERPROFILE%\.xqd_tool\ffmpeg\bin` | 一键安装的 ffmpeg / ffprobe |
| 下载目录 | 首次取注册表「下载」Known Folder（本机被重定向到 `D:\download`），改过就沿用 |

★ 凭据固定写在真实用户目录（不受 `XQD_TEST_HOME` 影响）；回归里 `save_cookie()`
在测试隔离状态下**拒绝写真实凭据**，但读取不受影响。

## 七、发版与交付

### 流程

```bash
# 版本号先改 csproj 的 PkgVersion，并同步 States.AppVersion / build.cmd
git add -A && git commit -m "feat/fix: …"
git push origin master
git tag -a v1.7.1 -m "v1.7.1：…"
git push origin v1.7.1        # ← 推 tag 才触发 Release
```

`release.yml`（`on: push tags v*`）依次做：

1. 还原 + 构建 `xqd-csharp/Xqd.sln` → 跑 `Xqd.Tests.exe`（不过就不发版）；
2. 按标签版本 `dotnet publish` 自包含单文件 → `xqd-avalonia/dist/xqd-downloader-v<ver>.exe`；
3. 核对**文件名与 FileVersion**是否跟标签一致；
4. 建 Release（`draft: false`，自动生成说明）并上传 exe。

`ci.yml` 在 push master / PR 时跑：C# 离线回归 → `python -m compileall xqd`（只验语法）→
用 `PkgVersion=0.0.0-ci` 试构建单文件 exe，防止“能编译但测试挂”的提交进主线。

### 交付口径

- **对外只给远程件**：Release 页面或资产直链。远端 exe 由 CI 在 tag 提交上重新构建，
  与本地 `build.cmd` 产出的 exe **不是同一份二进制**（本地件的 ProductVersion 会内嵌当时的提交号）。
- 本机 `dist/` 在 `.gitignore` 内，只作自测与排障，不作为交付物。
- `Xqd.Cli` / `Xqd.Server` 保留在仓库便于本地批处理与网页版调试，**不进 Release 资产**。

cd D:\xqd-downloader\xqd-avalonia
cmd /c build.cmd              # → dist\xqd-downloader-v1.7.1.exe
