## 5. 突破：PYZ 定制加密已破解（核心成果）

### 5.1 加密结构

新版 **没有**用标准 PyInstaller AES，而是把归档器换成了定制版：

- 冻结模块 `pyimod02_archive.pyc` 的原始文件名是
  **`pyimod02_archive_crypto_bootstrap.py`**（PyInstaller 标准版里没有这个后缀）。
- 它替换了标准 `Cipher` 类，用 `pyimod00_crypto_key.get_mask()` 派生的 16 字节掩码
  做**每 16 字节一列的替换表密码**（`translate`）。

完整反汇编见 `_lel/v2/pyimod02_archive.disasm.txt`。

### 5.2 密钥派生（已完整复现）

`pyimod00_crypto_key.pyc`（标准 PyInstaller 这里是 16 字节 AES key，这里被换成自定义 PRNG）：

```python
_seed    = 4272740770
_nonce   = [23,123,35,2,251,195,5,32,171,118,113,41,31,101,168,23]
_encoded = [3,231,101,222,225,130,253,174,37,181,102,116,220,58,177,239]

def _mix_state(state, nonce_item, index):
    state = (state + nonce_item + (index + 1) * 2654435761) & 0xFFFFFFFF
    state ^= (state << 13) & 0xFFFFFFFF
    state ^= state >> 17
    state ^= (state << 5) & 0xFFFFFFFF
    return state & 0xFFFFFFFF

def get_mask():
    state = _seed
    result = []
    for index, item in enumerate(_encoded):
        state = _mix_state(state, _nonce[index & 15], index)
        mask = ((state >> ((index & 3) * 8)) & 255) ^ ((index * 37 + 93) & 255)
        result.append(item ^ mask)
    return bytes(result)
```

派生结果：

```
mask = b0 5c 50 67 d4 16 25 dd 02 73 fa c1 b6 1d f1 0a
```

> 交叉验证：mask 的**后 8 字节与加密文件尾部 8 字节完全一致**，确认算法正确。

### 5.3 解密流程

```python
payload = data[16:]                                  # 跳过 16 字节头
result  = bytearray(len(payload))
for offset, table in enumerate(tables):              # 16 张 256 项替换表
    result[offset::16] = payload[offset::16].translate(table)
plain = zlib.decompress(bytes(result))               # → marshal code object
```

> 关键细节：`result[offset::16]` 是**步长 16 的三参数切片**，
> 即把数据按 16 列纵向切分，每列用各自掩码字节做字节替换。
> 第一次按普通连续切片理解会得到错误结果。

### 5.4 结果

```
decrypted ok: 2638, failed: 0
```

**2638 个模块 100% 解密**，产物在 `D:\Programs\rarwork\Mooc_Pyarmor`（51 MB）。

其中 **1847 个是明文**（标准库、第三方库，可直接反编译），
**791 个带 `__pyarmor__` 标记**（业务代码，二次加固）。

## 6. 剩余障碍：PyArmor 9.2.8 (pro)

### 6.1 版本与结构

`C:\LEL\LEL-Downloader\xuewuzhi_runtime\__init__.py`：

```python
# Pyarmor 9.2.8 (pro), 005383, 2026-11-03T11:17:40.540625
from .pyarmor_runtime import __pyarmor__
```

`pyarmor_runtime.pyd` 是 **32 位**（x86）扩展，与 `cp37-win32` 匹配。
因此必须用 32 位 Python 3.7 才能加载（已备好 `py37x86` 嵌入版解释器）。

### 6.2 三道锁

| 锁 | 位置 | 现象 |
|---|---|---|
| ① PYZ 流密码 | `pyimod02_archive` | ✅ **已破解** |
| ② PyArmor 授权 | `pyarmor_runtime.pyd` | `RuntimeError: unauthorized use of script (1:5174)` |
| ③ 运行时守卫 | `xwz_runtime_guard.pyd` (9 MB) | `ImportError: runtime guard initialization failed (7003/6948)` |

守卫的可读字符串暴露了它的机制：

```
journal directory must be text
incident journal already armed or unavailable
download process containment failed
server time must be an integer
Application integrity verification failed (code %u).
Please reinstall an official Xuewuzhi Downloader package.
```

它依赖：
- `C:\Users\<user>\AppData\Roaming\LEL-Downloader\` 下的
  `Config` / `Device` / `Device.identity` / `User` / `RuntimeIncidents` / `log.txt`
- 服务器时间同步（`update_server_time`）
- `core-integrity.bin` 里的文件 SHA256 清单

### 6.3 `core-integrity.bin` 格式（已解析）

```
magic  "XWZCORE2"   (8 bytes)
ver    u32 = 1
count  u32
entries:
    u16 path_len (字节数)
    UTF-16LE path
    u32  file_size
    32 bytes  SHA256
```

清单内含 `LEL-downloader.exe`、`python37.dll`、`xuewuzhi_runtime\pyarmor_runtime.pyd`、
`xwz_runtime_guard.pyd`、`certifi\cacert.pem` 等关键文件的哈希。

### 6.4 客户端已在运行

`AppData\Roaming\LEL-Downloader\.pid` 存在，`Config` 显示：

```json
{"data":{"log_cleared_version":"V2.19.70稳定版","update_cnt":0,"updated":false,
 "version":"V2.19.70稳定版"},"format":"XWZ_CONFIG","schema_version":2}
```

**即本机已通过授权与设备绑定校验，客户端本身是可用的。**

### 6.5 已排除的路径

- ❌ 直接 `import` 受保护模块 → `unauthorized use of script`（授权绑定设备+程序）
- ❌ `sys.settrace` 挂钩捕获解密后 code → 触发反调试，进程静默终止
- ❌ 手动调用 `__pyarmor__(blob)` → 进程静默终止（非法调用检测）
- ❌ 复制 pyd 到其他目录 → 守卫哈希校验失败（7003）；在原目录内 → 进程环境检查失败（6948）

**结论：PyArmor 这层需要更专业的脱壳手段（VMP 分析 / 内存 dump），不属于本次范围。**
