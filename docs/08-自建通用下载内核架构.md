# 学无止下载器 · 内核拆解与自建通用教学平台下载器

> 目标：不依赖第三方客户端的账号体系与界面，用**用户自己的平台权限**，
> 自建一个能覆盖兴趣岛、网易课堂（163）等教学平台的通用视频下载内核。
>
> 状态：兴趣岛登录链路已完全还原；163 视频地址解密内核已复现并通过官方样本回归。

---

## 一、核心结论：学无止的代码分三层，价值分布极不均匀

| 层 | 内容 | 加密强度 | 我们的处置 |
|---|---|---|---|
| ① **登录层** | `Login-Mooc/resources/app.asar`（Electron 8.5.5 明文 JS） | **无** | ✅ 完全复用 |
| ② **归档层** | PYZ 内 2638 个模块 | 定制流密码（已破） | ✅ 已全量解密 |
| ③ **业务层** | 791 个平台适配器 + `core` | PyArmor 9.2.8 pro + 运行时守卫 | ❌ 放弃硬破 |

**关键判断：①+② 的价值远大于 ③。**

学无止真正值钱的东西是它**逐个平台踩出来的接口细节**（Cookie 名、端点、
加密算法、密钥派生）。而这些细节有两条更高效的获取路径：

- 兴趣岛：官方前端 JS bundle **完全明文**，端点/参数/密钥全在里面（已还原）。
- 网易课堂 163：1.5.0 版本的 `Source/core` **明文可解**，解密算法已复现。

也就是说——**我们不需要破解 PyArmor 就能拿到想要的内核**。

## 二、层①：登录层是明文的，这是整个方案的支点

### 2.1 `login-mooc.exe` 是一个独立的通用登录器

从 `app.asar` 的 `package.json` 与 `main.js` 还原出的调用契约：

```
login-mooc.exe <cookies_file> <login_name> [extra_arg]
```

- `cookies_file`：登录成功后 Cookie 以 JSON 写入该文件
- `login_name`：平台标识（如 `qianliao`、`open163`、`imooc`…）

**这意味着我们可以只借用它的"扫码登录"这一个动作，完全不用它的下载器和账号体系。**

## 三、层②：PYZ 定制加密已破解（可复现）

### 3.1 指纹

归档器被替换为 `pyimod02_archive_crypto_bootstrap.py`（文件名即识别指纹）。
标准 `pyinstxtractor-ng` 能提取但**全部解密失败**（它只认标准 AES）。

### 3.2 算法

```python
# 密钥派生（pyimod00_crypto_key 的自定义 PRNG）
mask = b05c5067d41625dd0273fac1b61df10a

# 流密码：16 列纵向置换 + 每列字节替换表
def stream_crypt(data, mask):
    payload = data[16:]                       # 跳过 16 字节头
    result = bytearray(len(payload))
    for offset, table in enumerate(tables):   # tables[i][v] = v ^ mask[i]
        result[offset::16] = payload[offset::16].translate(table)
    return bytes(result)

# 归档读取：先流密码解密，再 zlib 解压
obj = zlib.decompress(stream_crypt(obj, mask))
```

**易错点**：`result[offset::16]` 是**三参数切片**（纵向切 16 列），
不是连续切片。按连续切片理解会解出垃圾数据。

### 3.3 成果

- 2638 / 2638 模块解密成功，零失败
- 1847 个明文可直接反编译；791 个带 `__pyarmor__` 标记
- 工具：`_lel/v2/xwz_pyz_decrypt.py`（一键批量）

## 四、层②附赠：网易课堂（163）视频地址解密内核 —— 已复现

来源：1.5.0 的 `Source/core.dec`（**明文 JS**，非 PyArmor）。

### 4.1 算法

```js
// 密钥派生：charListMap 索引 → charEnlist 查表
function L(v) {
  var t = charListMap["v_" + v], n = "";
  for (var a = 0; a < t.length; a++)
    n += charEnlist[t[a].t][t[a].i];
  return n;
}

// 解密
decryptAES(k, v):
  key = L(v)                              // 16 字节
  raw = base64decode(k)
  iv = raw[:16], body = raw[16:]
  plain = AES-CBC-PKCS7(key, iv, body)
  return JSON(plain up to first '}')

// 用法
url = videoUrl + "&token=" + decrypted.k
```

## 五、层③：为什么放弃硬破 PyArmor

| 障碍 | 现象 |
|---|---|
| 授权绑定 | `unauthorized use of script (1:5174)`，绑定设备 + 程序 |
| 运行时守卫 | `xwz_runtime_guard.pyd` 校验文件哈希，错误码 7003 / 6948 |
| 反调试 | `sys.settrace` 挂钩与手动调 `__pyarmor__` 均触发**静默杀进程** |
| 完整性清单 | `core-integrity.bin`（969 字节，18 条目，格式：`XWZCORE2` + ver + len + salt(16B) + count + 条目[u16 len + ASCII路径 + u32 size + 32B hash]） |

补充：即使成功解密，产出的也只是**编译后的字节码**，
还原成可维护源码还需跨版本反编译器（3.7 字节码）—— 成本远高于
「从明文前端 JS / 明文老版本重新推导」。

**结论：③④ 层不值得硬碰。用明文渠道拿等价信息，用工程能力补齐剩下的。**
